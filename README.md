# 极光 4 Pro / 6S 助手

为腾讯极光 4 Pro（A4111）和 6S（A4112）提供无线修复、RGB 灯条控制与 eMMC 双系统管理。
支持 6S、4 Pro RTL8852 和 4 Pro AP6275P，适用于 CoreELEC Amlogic-ng 21.x、Amlogic-no 22.x。

## 插件功能

### Wi-Fi、蓝牙与遥控器修复

- 自动识别 NG / NO 分支，通过原厂 Android 属性区分 A4111 / A4112；未挂载 Android 时按 `active_slot` 选择 A/B 元数据，临时只读映射完整 vendor 获取机型，读取后卸载。当前 DTB 的名称不作为实物机型依据。
- 硬件修复优先读取原厂 Android 型号区分 4 Pro（A4111）和 6S（A4112），不把当前 DTB 名称作为实物机型证据；A4111 / rev D 保留实物机型选择。无线版本优先采用已识别的 PCI 芯片 ID；未识别到已知 PCI 芯片时，4 Pro 才按 CPU 修订号推测（rev A/B/C 为 AP6275P、rev D 为 RTL8852），6S 使用 RTL8852。支持 rev B 配 RTL8852 的 4 Pro。
- 支持手动确认 4 Pro / 6S，适用于使用通用或 Ugoos X4 等设备树、且无法取得原厂机型的情况。
- RTL8852 NG 安装 Wi-Fi、灯条驱动并配置独立的开机启动服务，驱动加载不依赖 Kodi。
- RTL8852 NO 提供蓝牙配置；所有 NO 机型/无线版本均提供 Zidoo V12 输入识别修复，NG 不安装这条规则。
- AP6275P NG 使用系统自带的博通 Wi-Fi/蓝牙支持，安装专用 DTB 与独立灯条驱动服务；迁移时备份并清理旧 Realtek NG 驱动文件、配置和强制启动项。
- AP6275P NO 安装对应 DTB 及 V12 识别规则，使用 CE 自带的博通 Wi-Fi/蓝牙驱动和固件。
- 插件服务启动时核对当前专用 DTB，在没有蓝牙控制器且对应的系统蓝牙初始化服务明确失败时，自动重试一次；支持 NG/NO 的 AP6275P 与 RTL8852。同一次开机最多重试一次，正常运行、仍在初始化或已停用的服务不重启。检查独立于灯控运行，不新增常驻系统服务，不修改 DTB、固件或配对记录。
- 安装前检查兼容性并备份原文件，支持恢复；部署失败时尝试自动回退。

### RGB 灯条控制

- 分别设置常规状态和播放状态的颜色、亮度及效果。
- 支持常亮、呼吸和关闭，呼吸提供快、中、慢三档速度。
- 支持 Kodi 原生色块选色，也可精确输入 RGB 十六进制色值。
- 支持硬件平滑呼吸；可关闭平滑优先选项，以保留独立 RGB 亮度档位。
- 灯控运行依据已安装的专用 DTB 和灯控设备，不依赖 Android 机型读取；安装硬件修复仍单独核对机型。
- 开机后自动应用保存的设置，播放音频或视频时切换灯光，停止播放后恢复常规状态。
- 保存设置后按当前播放状态立即应用，支持查看当前灯光状态。

### eMMC 双系统、备份与还原（NO 22.x / NG 21.x 测试）

- 仅接受原厂 Android 属性明确识别的 **A4111 / A4112**，两者使用同一套流程，不按 Wi-Fi/蓝牙芯片区分。不接受通过借用 DTB 或手动确认绕过机型检查。
- **安装双系统**：将当前外置 CE（设置、插件及数据）迁入 eMMC；可按 1 GiB 步进选择 Android 用户数据容量（至少 8 GiB，不含系统分区）；扣除原厂系统分区、1 GiB CE 启动区和分区间隔后，其余空间分给 CE 数据区。仅提供能容纳当前 CE 数据及预留空间的选项。兼容此前固定 20 GiB CE 数据区布局的移除、备份与还原；再次调整容量需重新安装并重置 Android。保留 Android 系统分区，重置其应用、账号和用户文件。
- 启动区递归迁移 `/flash` 的文件和目录（含隐藏文件与空目录），排除根目录 `/flash/device_trees` 和 `/flash/aml_autoscript`；`cfgload` 继续使用当前 CE 已核验的原版，`config.ini` 保留配置并设置内置启动路径。安装前检查启动区容量，暂存和写入后校验完整清单与文件内容。NG/NO 均不迁移多启动初始化脚本，避免 NG tar 更新重置内置 CE 启动入口；在目前已检查的 NG 更新脚本中，这也会跳过同一条件块内的 `cfgload` 更新。
- 迁移 CE 时保留权限、ACL 与扩展属性；CE 未启用 SELinux 时跳过残留的 `security.selinux` 标签，兼容带此标签的外置系统盘。
- **移除内置 CE**：恢复原厂 userdata 的起点和容量，保留 Android 系统分区；内置 CE 和 Android 用户数据都将清除。Android 下次启动重新初始化。
- **修复双系统启动/布局**：检查现场分区与启动环境，只修复检测到的问题。NG 21.x / NO 22.x 支持修复已有双系统的启动扫描范围，并从残留 FAT32/ext4 元数据推断和恢复被 Android OTA 覆盖的布局，两种问题可一起处理，无需旧安装记录。正常状态不写入，未知布局/脚本拒绝覆盖。 修复入口独立读取 A/B vendor 的原厂机型，允许 `active_slot=normal`，可读机型必须唯一为 A4111/A4112；不会把 misc 槽位标记写回环境变量。Recovery 请求和 OTA 状态仅提示并原样保留，不代替 Android 选择启动槽位或完成升级。写入前只读校验 CE 文件系统和启动文件，保存原 DTB/MPT、env 和 misc，写后回读核验。不格式化、不主动重置 Android，不修改 A/B 槽位或 misc，不做整盘备份。布局恢复后需保留外置盘重启检查；仅启动修复后关机拔外置盘再正常开机。不能保证损坏数据可恢复，也不能防止再次 OTA 覆盖布局。
- **查看 eMMC 健康度**：显示芯片型号、容量、寿命估计 A/B 和备用块状态。通过内核只读接口查询，NG/NO、内置/外置 CE 均可查看，不需要挂载 Android 或安装双系统；不支持的指标显示不可用，不把寿命分档误报为精确健康百分比。
- **完整备份**：备份 eMMC 用户区、boot0、boot1，保存本机 CID/容量/机型及 SHA-256，并独立读回核验。备份不需要重启。
- **完整还原**：仅允许还原同一 eMMC、同一机型和容量的完整备份。写入前对全部镜像各完整校验一次，再写入、读回验证；分别显示校验、写入和读回进度；boot0/boot1 内容相同时跳过写入。缺少 CID 的旧研究备份，只有补充经核对的历史身份记录后才能被识别；原始记录和镜像保持不变，执行还原前仍完整校验镜像。
- 还原写盘前暂停占用 Android 分区的 TEE 服务；写盘前失败会恢复原先运行的服务，写入后保持暂停直到重启。
- 安装、移除、布局修复、备份和还原必须从 **外置 SD / USB 的 CE** 发起，备份保存在外置 `/storage/aurora-emmc-backups/`。手动备份需要容纳一份完整 eMMC 镜像的可用空间；安装需要 CE 快照和暂存空间，移除、还原不再预留整盘备份空间。
- **仅“完整备份”入口会生成整盘备份**。安装、移除、还原都不自动备份，也不要求已有备份；如需保留当前状态，应先手动备份。安装时暂存当前外置 CE 用于迁移，不是 eMMC 备份。
- 安装/移除写盘前明确提示 **Android 将重置**；完整还原提示数据覆盖；布局修复单独说明不主动清空数据但存在损失风险。各入口均有对应免责与操作期间禁止断电等提示，用户取消不会启动任务。
- 操作在插件前台执行，显示百分比和“已处理 / 总量”（含复制、校验各阶段），不再创建 systemd 后台写盘任务。安装保持 Kodi 运行；开始前请停止播放、媒体库同步、扫描和刮削，操作期间不要退出 Kodi。写盘前可以请求取消，写盘开始后不能取消。
- 安装保留文件的扩展属性和访问控制属性，即使系统 rsync 未编译相关支持也会单独复制并校验。安装复制当前外置 CE 到暂存目录，不再检查运行中源文件是否保持不变，也不对 SQLite 做专门快照；用户需按提示停止相关活动。暂存文件及写入 eMMC 后的读回校验保留。
- 安装通过严格限定起点、长度的 loop 设备完成写入，**不需要中途重启**；完成后关机、拔下外置盘再开机。安装器不会自动重启。
- 仅接受已核对的 MPT 布局和启动脚本，不能用于第三方任意双系统布局。备份不包含 RPMB/eFuse/硬件配置，不是线刷包，也不保证硬件绑定加密数据一定可恢复。

### 启动第一屏

- 查看当前第一屏，选择 PNG/JPG/BMP 图片并预览、更换 Android/CE 共用的开机第一屏。
- 恢复内置、校验过的原厂“腾讯极光 / 互联八方”素材。素材来自 6S，当前测试 4 Pro 使用相同资源包；以预览显示的图片为准。
- 图片等比缩放居中，空白及透明区域为黑色；原厂素材压缩存放，使用时解压校验。
- 仅写入独立 Logo 分区，不清空应用或用户数据；写前保存压缩备份，写后读回校验，重启后生效。无需常驻服务。
- 需要系统 Python 提供 Pillow；支持机型与分区检查通过后才允许写入。写入期间不能断电或拔盘。

NO 硬件修复默认安装 HS400 DTB，标识带 `_hs400` 后缀；NG 保持原设置。
当前 HS400 基础读写验证来自 4 Pro/AP6275P，其他硬件版本仍需实机验证。
只更新插件不会自动改写当前启动 DTB，需从“修复硬件”安装后重启生效。

1.6.10 将修复入口统一为“修复双系统启动/布局”，新增 NG/NO 的 cfgloademmc 扫描范围修复；保留 NO 布局恢复检查，安装/移除流程不变。

1.6.11 修正 NG 修复时 dm-linear 别名导致的只读状态误判，改用块设备 BLKROGET 查询；保留拒绝可写映射的检查。

1.6.12 取消双系统启动/布局修复对 kernel.img.md5 和 SYSTEM.md5 的依赖，避免 tar 升级后旧校验文件误拦截。仍检查只读映射、文件系统、启动脚本与配置和镜像基本格式；现场 SHA256 用于检测检查前后文件变化，不代表发行方完整性认证。不修改原 MD5 文件；备份/还原校验保持不变。


### 1.6.14：恢复 OTA 目标槽启动

“修复双系统启动/布局”增加 Android 11 完整 Virtual A/B 快照的受限恢复。依据盒子现场的 metadata、super/GSI 映射、misc 和快照数据确认来源槽与目标槽，不需要 `update.zip`、升级前备份或历史安装记录，也不将持久化 `active_slot` 当作唯一依据。

- 布局被覆盖时：先完整检查快照，再恢复 DTB/MPT 和启动扫描范围，仅清除明确的 `init_user0_failed` Recovery 命令，保留 A/B。正常重启到外置 CE 后，再次运行同一功能。
- 布局正确时：重新检查现场并完整读取目标快照，设置目标槽优先级和 6 次尝试，保留来源槽，不伪造启动成功。不修改环境变量 `active_slot`，不写快照、Android 系统镜像或用户数据。
- 完成后，按提示从 CE 菜单选择“从内部存储启动”进入 Android，由 Android 自己确认成功并合并快照。插件不自动重启，也不自动发起升级。
- 仅接受已验证格式的完整快照和未合并状态；增量依赖旧块、合并中、未知 Recovery、槽位记录冲突或已经消耗尝试次数均拒绝重新激活。已恢复或已完成的设备不会重复补充次数。检查和执行绑定同一份确认方案。
- 两阶段均要求外置 CE，沿用前台进度和写盘锁。每次保存修改前的 DTB/MPT/env/misc；目标槽恢复另存 metadata 和 super 映射元数据。它们不是整盘备份，Android 合并后不能仅靠这些旧记录回滚。

独立实验已在一台 4 Pro 的 NG 环境中恢复目标 B 槽 Android 8.51.00，确认 `MergeCompleted`、启动成功标记以及内置 CE/Android 双向启动。插件集成版通过离线故障注入和恢复完成机器的只读检查；NO 共用同一受限流程，尚未重复制造 OTA 故障实测。


### 1.6.15：NO OTA 恢复兼容

修正 NO 自动只读挂载 Android system/vendor 时误拒绝 OTA 检查的问题：只允许经只读 ioctl、挂载点和线性映射边界核验的 dynpart super 视图，其余占用仍拒绝。metadata 读取按分支选择后端：NO 使用已验证的只读 loop，NG 保持 dm-linear；不停止或卸载正常 Android 库挂载。

增加已由 Android 标记目标槽成功、但仍有完整未合并快照及 init_user0_failed 请求的受限分支：恢复布局、清理已核验 BCB 命令，保留所有 A/B 字节，不重选槽位或补次数。布局与请求已正常时只提示启动 Android 完成验证及合并。

在 50.148 外置 NO 的真实 OTA 故障现场，已通过只读检查，恢复候选为 1 GiB CE 启动区、46.77 GiB CE 数据区与 8 GiB Android 用户区；同时验证了 super+userdata 混合 COW 映射。预检前后 DTB/MPT/env/misc/metadata 哈希一致。实际写入及 Android 启动验证仍待完成。


### 1.6.16：修复前恢复 CE ext4 日志

“修复双系统启动/布局”在用户确认后，识别内置 `ce_storage` 的 ext4 needs_recovery 状态，先保存超级块和 e2fsck 撤销记录，仅执行 `e2fsck -p -E journal_only -z ...`，然后完整只读检查。未通过则停止，不继续修改布局或启动状态。不会执行全面可写 fsck，不格式化，不处理 Android userdata 的日志。干净分区不执行此写入。

要求外置 CE 启动，确认设备与推导边界、分区未使用、CE 数据目录和内置日志格式，撤销记录位于本次任务的 `ce-journal` 目录；额外要求外置盘至少 1 GiB 空间。NG 使用有边界的 dm-linear，NO 使用有边界的 loop。撤销记录不是完整备份，不能保证断电恢复，也不能在后续使用文件系统后直接回滚。
